# Architecture Specification: Gemini 4 Argon Babysitting Experiment

## 1. Overview & Objectives

The "Babysitting Argon 4" experiment evaluates the operational behavior, reasoning fidelity, and proxy stability of Google's Gemini 4 Argon (`gemini-4-argon`) agent running against the local `gemini2api` reverse-engineered proxy.

The experiment employs a 3-role autonomous loop:
```
           +---------------------------------------------+
           |       Orchestrator (gemini-3.8-flash)       |
           |   Generates structured tasks (task.schema)  |
           +----------------------+----------------------+
                                  |
                                  v
+---------------------------------+----------------------------------+
|                   Argon 4 Agent (gemini-4-argon)                   |
|  Executes task turns in an isolated sandbox with tool execution    |
+---------------------------------+----------------------------------+
                                  |
            [Proxy Telemetry & Execution Traces]
                                  |
                                  v
           +----------------------+----------------------+
           |          Monitor (gemini-3.8-flash)         |
           | Correlates proxy metrics, logs & findings   |
           +---------------------------------------------+
```

## 2. Roles and Request Attribution

Because `gemini2api` uses a shared administrative `API_KEY` without per-agent keys, all callers identify their traffic using custom HTTP headers:
- `X-G2A-Run`: `<run_id>` (e.g. `20261017-argon-exp1`)
- `X-G2A-Role`: `orchestrator` | `agent` | `monitor`

Validation rules enforced by `gemini2api`:
- Characters: `^[A-Za-z0-9_.:-]+$`
- Maximum length: 64 characters per header
- Maximum count: 2 tags recorded into `LogRecord.tags` and `debug_metrics.records[].tags`

## 3. Data Layout & Artifacts

All run artifacts reside strictly under `runs/<run-id>/`:
```
runs/<run-id>/
├── tasks.jsonl        # Tasks generated by Orchestrator (task.schema.json)
├── argon_trace.jsonl  # Full conversational turn history & tool calls of Argon
├── timeline.jsonl     # Correlated timeline merging proxy debug-metrics, logs, & refresher events
├── metrics.jsonl      # Periodic metrics snapshots (TTFT percentiles, stall rates, pool status)
├── findings.jsonl     # Monitor findings backed by concrete evidence (finding.schema.json)
└── sandbox/           # Isolated directory for tool execution (file read/write, local commands)
```

### Crash Recovery & Resume
- Every task in `tasks.jsonl` has a unique `task_id`.
- The runner checkpoints completed `task_id`s in `runs/<run-id>/completed_tasks.json`.
- On crash or restart with `--resume <run-id>`, the runner loads `completed_tasks.json` and skips previously executed tasks without duplicating turns or corrupting traces.

## 4. Signal Ingestion & Telemetry

### Endpoint Signals
- `GET /admin/debug-metrics`: Provides ring buffer of recent requests (up to 200 items), including `request_id`, `ts`, `model`, `served_by`, `ttft_ms`, `total_latency_ms`, `error_class`, and `tags`. Polled every 4 seconds by `collector.py` to prevent ring overflow.
- `GET /admin/logs`: Provides structured log records with filtering by search and direction.
- `GET /admin/status`: Provides real-time pool health (total, active, expired accounts) and circuit breaker status.
- Docker logs (`gemini2api-refresher`): Real-time observation of cookie rotations, session reloads, and skipped sources.

### Redaction & Privacy Doctrine
- `gemini2api` enforces strict redaction: no Google session cookies (`__Secure-1PSID`, `__Secure-1PSIDTS`), API keys, or raw `accounts.json` credentials are ever logged or exported.
- Per-account correlation is done using one-way account hashes (`account_hash`).
- `log_bodies_enabled` (D2): Remains `false` in production. Only temporarily enabled during the experiment for synthetic sandbox verification, and never captures streaming tokens. Full agent traces must be written by the client/runner into `argon_trace.jsonl`.

## 5. Safety Fuses & Operating Constraints

- **D3 (Strict Concurrency = 1):** Exactly ONE Argon task may be in flight at any given moment. Parallel Argon requests risk pool saturation and mid-thinking race conditions.
- **D5 (Task Ceiling):** Maximum of 20 tasks per run session unless explicitly extended by the operator.
- **Argon Timeout:** Minimum 360 seconds per Argon task (`ARGON_TIMEOUT=360`). Argon extended thinking regularly exhibits TTFT between 120 and 260 seconds under high reasoning effort.
- **Configuration Invariant (D1):**
  - `ARGON_FALLBACK_TO_FLASH=false`: Disables silent substitution with Flash Thinking.
  - `ARGON_STALL_BREAKER_SECONDS=0`: Disables the 180s fallback circuit breaker window.
- **Kill-Switch:** Creating a file named `STOP` or `STOP_BABYSIT` inside `runs/<run-id>/` or the repository root immediately signals all daemons to halt gracefully.
- **Auto-Stop on Failure Threshold:**
  - 5 consecutive 5xx errors from the proxy.
  - 0 active accounts detected in `/admin/status`.
